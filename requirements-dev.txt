# Python development/test dependencies for the suite in test/python/.
#
# The suite runs under both of the container's interpreters (see the Dockerfile): the app's `python3` for
# label_clustering.py, which runs in-band under prod's 3.8, and `python3.13` for the offline tooling. Environment
# markers give each one the newest release it can take, so the 3.13 side isn't held back by the EOL interpreter:
#
#   python3    -m pip install -r requirements.txt -r requirements-dev.txt
#   python3.13 -m pip install -r requirements-offline-tools.txt -r requirements-dev.txt
#
# The boundary is 3.10 because that is pytest 9's floor, not because of anything on the 3.8 side: 8.3.5 / 5.0.0 are
# the last releases supporting 3.8 *and* the first pytest line supporting 3.13, so they cover the whole 3.8–3.9 gap
# and the legacy pin is not simply an older one. Keep the two ranges adjacent — a gap would leave an interpreter with
# no pin at all, and a marker that hands pytest 9 to something below 3.10 hard-errors instead of falling back.
pytest==8.3.5; python_version < "3.10"
pytest-cov==5.0.0; python_version < "3.10"
pytest==9.1.1; python_version >= "3.10"
pytest-cov==7.1.0; python_version >= "3.10"
