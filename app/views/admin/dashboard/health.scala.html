Nightly jobs #

Every background job this city runs overnight, with its last recorded run. A job whose results only ever reached the log left no evidence when it stopped firing — a silently dead poller looks exactly like a quiet night — so each run is recorded as it happens. Watch the Last run column: anything overdue, failed, or never run means that pipeline has stopped feeding whatever depends on it. Times are Pacific, before this city's scheduling offset.

Blocking locks #

Sessions that are currently blocking one or more others from acquiring a lock. A session that holds a strong lock (for example on street_edge) while idle in a transaction can silently stall every reader of that table. Ordered worst-first.

Long-running queries #

Client queries that have been running for a while. One runaway query — an expensive aggregate, a missing index — can saturate the database without blocking anyone, so it won't show up in the locks panel above. Oldest first.

Idle transactions #

Sessions sitting in an open transaction while idle. A leaked transaction that never commits or rolls back holds its locks the whole time, so long-lived rows here are worth investigating. Oldest first.

Stuck evolutions #

Play evolutions that are mid-apply or carry a recorded problem, across every city schema. A failed evolution keeps a city's app instance from coming up cleanly.

Table bloat & autovacuum #

Dead-tuple bloat and last-vacuum age for the heavyweight tables (street_edge, label, audit_task_interaction, validation_task_interaction) across cities. High bloat with a stale last-vacuum means autovacuum is falling behind — often because it can't get a lock.

DB connections #

Client-backend connections grouped by role and state. Each city's app instance connects as its own per-city role with its own pool ceiling, so a role whose active connections approach that ceiling is under pressure.

Media storage #

Media that must outlive a deploy, and whether any of it is gone. A deploy rebuilds the whole build tree, so anything kept inside it dies with the next release while its database rows survive — how #4925 destroyed a story photo. Missing is a row with no file; orphaned is a file with no row.

Pano downloads #

Backup-image coverage for this city's labeled panos. The viewer shows a locally-hosted backup when one exists and otherwise falls back to the live source, so a labeled pano whose source has expired and has no backup can no longer be shown.
